# Teaching Portal

This repository is a production-style Docusaurus teaching portal for Master's and Bachelor's courses. It is organized so that:

- course metadata is managed in typed data files
- course content is authored in `docs/`
- reusable UI lives in `src/components`
- top-level site routes stay small and compositional in `src/pages`

The project is intentionally structured for long-term growth across many courses and teaching cycles.

## Adding a New Master's Course

1. Add the course description to [courses-descriptions.md](./courses-descriptions.md).
2. Add or update the matching course definition in [scripts/syncCoursesFromDescriptions.mjs](./scripts/syncCoursesFromDescriptions.mjs).
   Include the real title, level, credits, short description, tags, delivery mode, and the structured content used to generate the docs pages.
3. Run:

```bash
npm run sync:courses
```

4. The sync command updates [src/data/courses.ts](./src/data/courses.ts) and generates the standard docs folder under `docs/masters/<course-slug>/`.

Once the sync has run, the homepage and the Master's catalog page update automatically.

## Adding a New Bachelor's Course

1. Add the course description to [courses-descriptions.md](./courses-descriptions.md).
2. Add or update the corresponding entry in [scripts/syncCoursesFromDescriptions.mjs](./scripts/syncCoursesFromDescriptions.mjs).
3. Run:

```bash
npm run sync:courses
```

4. The sync command updates [src/data/courses.ts](./src/data/courses.ts) and generates the standard docs folder under `docs/bachelors/<course-slug>/`.

The Bachelor's catalog and the shared course grids will pick the new course up automatically.

## Adding a New Shared Resource

1. Add a resource entry in [src/data/resources.ts](./src/data/resources.ts).
2. If the resource is documentation-based, create a corresponding MDX file in `docs/resources/`.
3. If the resource points to an external site or template repository, use the external URL directly in the resource metadata.
4. Use tags deliberately so the resource cards remain useful as the library grows.

The homepage resources section and the `/resources` page both render from the same resource data.

## Maintenance Guide

### Where course metadata lives

The UI reads course catalog metadata from [src/data/courses.ts](./src/data/courses.ts), but the upstream authoring source for the current course set is [courses-descriptions.md](./courses-descriptions.md) together with the sync mapping in [scripts/syncCoursesFromDescriptions.mjs](./scripts/syncCoursesFromDescriptions.mjs).

### Where course docs live

Generated course content lives in `docs/masters/` and `docs/bachelors/`. Each course has its own folder and a repeatable content structure so the docs sidebar stays predictable across courses.

### How top-level pages are composed

Top-level routes in `src/pages/` are intentionally thin. They assemble reusable components and pull structured content from `src/data/` rather than embedding long page-specific content directly into TSX files.

### Which folders are for reusable components vs content

- `src/components/` is for reusable UI only
- `src/data/` is for structured metadata and page configuration consumed by the UI
- `docs/` is for teaching content
- `src/pages/` is for route entry points
- `src/css/` is for global design tokens and site-wide styling
- `scripts/` is for maintenance helpers such as syncing course metadata and docs from source descriptions

## Notes

- The blog is intentionally disabled.
- The docs sidebar is autogenerated from the real course and resource folders.
- The repository has been cleaned of starter-template pages and unused example content so the source tree reflects the actual portal architecture.
